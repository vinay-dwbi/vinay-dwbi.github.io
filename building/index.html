In development

A two-sided local marketplace

The interesting part is not the marketplace. It is who can see what.

Authorization lives in the database, as row-level security, rather than in application code. The reason is failure direction: a missed row-level policy denies access, while a missed application check leaks data. A bug that locks someone out is easier to live with than one that shows them someone else's data.

User requests and system jobs reach the data on separate paths. A user request carries that user's identity, and the database enforces what the identity can see. System work runs on a separate privileged path, and lint rules on imports keep application code from reaching for it. A per-role test suite checks the policies before changes ship.
