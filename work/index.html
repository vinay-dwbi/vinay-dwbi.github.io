Selected work

eHealth

Customer identity resolution

The same person reaches us three ways: as an application in the back office, as a web lead in Adobe clickstream, and as an inbound phone call. Each source describes them differently, and none of them is wrong on its own terms.

I rebuilt the process that resolves them to a single Master ID. It moved from Oracle to Snowflake on Databricks, and rule-based matching gave way to ML-based matching with H2O.ai on distributed compute. Validating the rewrite also found defects in the legacy logic. The new process refreshes more often and matches more accurately.

Identity resolution · Machine learning · Snowflake · Databricks

eHealth

New sources as configuration

When every new source is a bespoke project, the tenth costs what the first did. I built a component library so that a new source is a configuration entry.

A parameterized ingestion component creates Snowflake tables dynamically and normalizes naming. A count-validation wrapper reconciles every load. Backup tables follow a standard that carries provenance and retention metadata. The data dictionary generates itself into Confluence.

Ingestion · Reconciliation · Metadata
