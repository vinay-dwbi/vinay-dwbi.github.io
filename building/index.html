A two-sided local marketplace

The interesting part is not the marketplace. It is who can see what.

I put authorization in the database, as row-level security, rather than in application code. The reason is failure direction: a missed row-level policy denies access, while a missed application check leaks data. I would rather ship a bug that locks someone out than one that shows them someone else's data.

User requests and system jobs reach the data on separate paths. A user request carries that user's identity, and the database enforces what the identity can see. System work runs on a separate privileged path, and lint rules on imports keep application code from reaching for it. A per-role test suite checks the row-level policies before changes ship.
